# mesync 品味维护

品味是项目积累的「代码偏好」——用户在代码结构、编写风格、命名习惯、文件组织、架构取舍等方面的偏好。与 wiki（项目是什么）不同，品味描述「用户喜欢什么样的代码」。

## 品味从哪里来

品味在和用户协作中**自然产生**，有两个来源：

1. **从决策中提取**：记录决策时，若决策体现了用户偏好，在决策的 `taste_signals` 字段带上（「决策 → 品味」的因果关联）。

2. **从用户反馈中识别**：观察用户的反馈与措辞——肯定某写法（「这样才对」）、否定某写法（「不要这样」）、表达偏好（「我喜欢…」「统一用…」）、某处反复调整反映的隐含偏好。

## 品味存在哪里

存在 `.mesync/tastes/` 下的 md 里：

```
.mesync/tastes/
├── overview.md   # 品味速览：各分类 + 一句话简介（索引）
└── <分类>.md     # 某角度的品味（分类名由你根据实际品味自然命名）
```

- **不预设分类**：分类根据实际产生的品味「自然长出来」，不套固定清单。
- **分门别类**：品味不能全堆在一个文档（会膨胀）。按代码结构、风格、命名、文件组织等角度拆分。
- **分类因项目而异**：不同用户、不同项目分类不同。

## 怎么记录

识别到新品味时：

1. 判断属于哪个角度——有对应分类文件则更新，没有则新建。
2. 用 `write` 写入 `.mesync/tastes/<分类>.md`（路径以 `.mesync/tastes/` 开头），自然语言描述，带上例子或来源。
3. 维护 `tastes/overview.md`，确保每个分类都有一行简介索引。

## 品味怎么用

开发时主动参考已有品味；需速览读 `tastes/overview.md`，需细节读对应分类文件。

## 原则

- **自然沉淀**：观察真实反馈总结，不硬造品味。
- **准确可追溯**：带上来源（哪次决策/反馈体现）。
- **克制**：不确定是否「稳定偏好」先不记，宁缺毋滥。
