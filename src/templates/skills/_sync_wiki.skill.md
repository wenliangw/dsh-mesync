# mesync Wiki 生成心法

本文件讲「怎么更好地生成 wiki」。文档结构、各文档要求见 `.mesync/rules/_sync_wiki.rule.md`，这里不重复。

## 核心心法

### 1. 只基于真实文件，杜绝臆测

写进 wiki 的内容都必须能在工作区真实文件里找到依据。文件里没有的信息，标注「未知」，禁止凭经验补全、编造依赖/配置/模块/功能。宁可少而准，不要多而假。

### 2. 先探索，后生成

不要一上来就写。顺序：`glob` 列目录 → 读关键入口（package.json / tsconfig / README / 各模块 index）→ `grep` 定位依赖关系 → 读够了再动笔。

### 3. 用证据说话

技术栈、依赖版本从配置文件核实；模块划分基于目录结构 + 真实代码；调用关系从 import / 引用里找。每条结论尽量能追溯来源文件。

### 4. 克制，不过度发挥

overview 是「速览」不是「详述」；没明显业务领域的项目，business 文档如实说明或留空，不硬编造。保持简洁、准确、可追溯。

## 输出方式

用 `write` 工具把每个文档写入 `.mesync/` 下（`path` 以 `.mesync/` 开头）。写完所有文档后调用 `mesync_sync_wiki` 同步索引。没有明显业务/架构时可少写，不硬凑。
